## 功能概述

知识库功能是一个基于 Markdown 文档的文档管理系统，允许用户将 Markdown 文件放入 `public/KnowledgeBase/` 文件夹，系统会自动：

1. ✅ 读取文件夹下的所有 Markdown 文档
2. ✅ 在左侧菜单生成"知识库"一级菜单
3. ✅ 将文档列表作为子菜单显示
4. ✅ 使用 `marked` 库解析 Markdown 并渲染为 HTML
5. ✅ 支持标准 Markdown 语法和 GitHub Flavored Markdown (GFM)

### 主要特性

- 🚀 **零配置**: 只需将 `.md` 文件放入文件夹，无需额外配置
- 📝 **标准语法**: 支持标准 Markdown 和 GFM 扩展
- 🎨 **自动样式**: 内置美观的 Markdown 渲染样式
- 🔄 **动态加载**: 刷新页面即可看到新增文档
- 📱 **响应式设计**: 完美适配各种屏幕尺寸

## 使用指南

### 1. 添加文档

#### 步骤一：创建 Markdown 文件

在 `public/KnowledgeBase/` 文件夹下创建 `.md` 文件，例如：

```
public/KnowledgeBase/
├── README.md
├── Vue3基础教程.md
├── JavaScript高级特性.md
└── TypeScript类型系统.md
```

#### 步骤二：更新文件列表

打开 `public/KnowledgeBase/files.json`，在 `files` 数组中添加新文件名：

```json
{
  "files": [
    "README.md",
    "示例文档.md",
    "Vue3基础教程.md",
    "JavaScript高级特性.md",
    "TypeScript类型系统.md"
  ]
}
```

#### 步骤三：刷新页面

刷新浏览器页面，新文档会自动出现在左侧菜单的"知识库"下。

### 2. 文件命名规范

#### 推荐命名方式

- ✅ `Vue3基础教程.md` - 使用中文，清晰明了
- ✅ `JavaScript-ES6-Features.md` - 使用英文和连字符
- ✅ `TypeScript_类型系统详解.md` - 混合使用，支持下划线

#### 避免的命名方式

- ❌ `My Document.md` - 包含空格
- ❌ `文档@2024.md` - 包含特殊字符
- ❌ `test#1.md` - 包含特殊符号

> **注意**: 虽然系统会处理特殊字符，但推荐使用简洁的命名，以文件名会直接显示在菜单中。

### 3. 查看文档

1. 点击左侧菜单的"知识库"
2. 展开后显示所有文档列表
3. 点击文档名称即可查看内容
4. 文档会自动解析 Markdown 并显示

### 4. Markdown 语法支持

系统支持以下 Markdown 特性：

#### 基础语法

```markdown
# 一级标题
## 二级标题
### 三级标题

**粗体文本**
*斜体文本*
~~删除线~~

- 无序列表项1
- 无序列表项2

1. 有序列表项1
2. 有序列表项2

[链接文本](https://example.com)
![图片描述](image.png)
```

#### 代码块

````markdown
```javascript

  console.log('Hello, World!');
}
```
````

#### 表格

```markdown
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| 数据1 | 数据2 | 数据3 |
```

#### 引用

```markdown
> 这是一个引用块
> 可以包含多行内容
```

#### GitHub Flavored Markdown (GFM)

- 任务列表
- 表格
- 自动链接
- 删除线
- 代码块语法高亮


### 数据流程

1. **初始化阶段**
   ```
   App.vue mounted
   → menuStore.loadKnowledgeBaseFiles()
   → getKnowledgeBaseFiles()
   → fetch('/KnowledgeBase/files.json')
   → 解析 JSON
   → 过滤文档列表
   → 生成菜单项
   → 更新 menuStore.menuItems
   ```

2. **文档加载阶段**
   ```
   用户点击菜单项
   → 路由跳转到 /knowledge-base/:filename
   → KnowledgeBase.vue 组件加载
   → findFileNameByRoute()
   → loadMarkdownFile(filename)
   → fetch('/KnowledgeBase/filename.md')
   → marked.parse(markdown)
   → 渲染 HTML
   ```

### 核心技术点

#### 1. Markdown 解析

使用 `marked` 库解析 Markdown：

```javascript
import { marked } from 'marked'

// 配置 marked
marked.setOptions({
  breaks: true,  // 支持 GitHub 风格的换行
  gfm: true,     // 启用 GitHub 风格的 Markdown
})

// 解析 Markdown
const htmlContent = marked.parse(markdownText)
```

#### 2. 动态路由

使用 Vue Router 的动态路由功能：

```javascript
{
  path: '/knowledge-base/:filename?',
  name: 'KnowledgeBase',
  component: KnowledgeBase
}
```

`?` 表示 `filename` 参数是可选的，当没有参数时显示文档列表。

#### 3. 菜单动态生成

在 `menuStore.js` 中动态加载菜单：

```javascript
const loadKnowledgeBaseFiles = async () => {
  const files = await getKnowledgeBaseFiles()
  const children = files.map((file, index) => ({
    index: `kb-${getDisplayName(file)}`,
    title: getDisplayName(file),
    path: getRoutePath(file),
    sort: index + 1,
    children: []
  }))
  knowledgeBaseMenu.children = children
}
```

#### 4. 路径处理

处理 Vite 的 base 路径配置：

```javascript
const baseUrl = import.meta.env.BASE_URL || '/'
const isDev = import.meta.env.DEV

// 开发环境使用根路径
// 生产环境使用 base 路径
let url = isDev 
  ? '/KnowledgeBase/files.json'
  : `${base}/KnowledgeBase/files.json`
```

## 实现细节

### 1. 文件路径处理

#### 开发环境 vs 生产环境

- **开发环境**: Vite 会直接从根路径提供 public 文件夹的内容
- **生产环境**: 需要考虑 `vite.config.js` 中的 `base` 配置

```javascript
// vite.config.js
export default defineConfig({
  base: '/haonanKnowledgeBase/', // GitHub Pages 路径
})
```

代码会自动处理这个差异，确保在两种环境下都能正常工作。

### 2. 路由路径生成

将文件名转换为路由友好的路径：

```javascript
function getRoutePath(filename) {
  const name = filename.replace(/\.md$/i, '')
  const routeName = name
    .replace(/[^\w\u4e00-\u9fa5-]/g, '-') // 替换特殊字符
    .replace(/-+/g, '-')                   // 合并多个连字符
    .replace(/^-|-$/g, '')                 // 去掉首尾连字符
  return `/knowledge-base/${encodeURIComponent(routeName)}`
}
```

### 3. 文件名匹配

当用户访问文档时，需要从路由参数中找到对应的文件：

```javascript
async function findFileNameByRoute() {
  const routeName = decodeURIComponent(route.params.filename)
  const files = await getKnowledgeBaseFiles()
  
  for (const file of files) {
    const fileRouteName = getRoutePath(file).split('/').pop()
    if (fileRouteName === routeName) {
      return file
    }
  }
  return null
}
```

### 4. 错误处理

系统包含完善的错误处理机制：

- ✅ 文件不存在时显示错误提示
- ✅ 网络请求失败时自动重试
- ✅ 文档列表为空时显示友好提示
- ✅ 控制台输出详细日志用于调试

### 5. 样式设计

Markdown 渲染样式特点：

- **标题**: 不同级别的标题有不同的字号和颜色
- **代码块**: 深色背景，语法高亮
- **链接**: 蓝色，悬停时变色
- **表格**: 斑马纹，悬停高亮
- **引用**: 左侧蓝色边框，浅灰背景

## 常见问题

### Q1: 添加文档后菜单没有更新？

**A**: 请确保：
1. ✅ 文件已放入 `public/KnowledgeBase/` 文件夹
2. ✅ 在 `files.json` 中添加了文件名
3. ✅ 刷新了浏览器页面（可能需要硬刷新 Ctrl+F5）

### Q2: 点击文档显示 404 错误？

**A**: 可能的原因：
- 文件名与 `files.json` 中的不一致
- 文件名包含特殊字符导致路由匹配失败
- 文件不存在或路径错误

**解决方法**:
- 检查文件是否真实存在
- 确认 `files.json` 中的文件名正确
- 查看浏览器控制台的错误信息

### Q3: Markdown 渲染不正确？

**A**: 检查：
- ✅ Markdown 语法是否正确
- ✅ 是否使用了不支持的语法
- ✅ 文件编码是否为 UTF-8

### Q4: 开发环境和生产环境路径不同？

**A**: 系统已自动处理这个差异：
- 开发环境使用根路径 `/KnowledgeBase/...`
- 生产环境使用 base 路径 `/haonanKnowledgeBase/KnowledgeBase/...`

如果仍有问题，检查 `vite.config.js` 中的 `base` 配置。

### Q5: 如何支持代码语法高亮？

**A**: `marked` 库本身不提供语法高亮，如需高亮可以：
1. 引入 `highlight.js` 或 `prism.js`
2. 配置 `marked` 使用自定义渲染器
3. 在样式中添加高亮主题
